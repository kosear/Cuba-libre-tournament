# Cuba Libre — требования и решения

Здесь записано, что мы обсудили и решили по сайту. Файл пополняется по ходу обсуждения.

## Как мы работаем

- **Код не трогаем, пока заказчик прямо не скажет начинать.** Сначала обсуждаем и согласуем план, потом пишем код.
- Новые функции сначала записываем в раздел «Новые функции», уточняем их и только после согласования реализуем.
- Нерешённые вопросы хранятся в [open-questions.md](open-questions.md). Когда вопрос решён, ответ переносится сюда.

## Что это за сайт

Сайт для турнира по бильярду. На нём:
- турнирная таблица;
- текущие группы;
- очередь матчей;
- подсчёт очков;
- админ-панель для управления игроками и счётом.

## Правила турнира (согласовано)

### Игра
- Играем в **пул-8**.
- **Каждый матч — одна партия (race to 1)**: и в группах, и в плей-офф.

### Групповой этап
- Внутри группы каждый играет с каждым.
- Число групп и игроков в группе не ограничено. По умолчанию **4 группы по 4 игрока**.
- **За победу в группе — 1 очко.**
- **Шары.** Победитель получает дополнительные очки: по одному за каждый шар соперника, оставшийся на столе (0–7). Они нужны, чтобы различать игроков с равным числом побед.
- **Места в группе определяются по порядку:** очки → шары → новый личный матч между равными игроками.

### Выход в плей-офф
Плей-офф — это полуфиналы и финал, всего 4 участника.

| Групп | Кто проходит |
|---|---|
| 1 | топ-4 группы |
| 2 | по 2 лучших из каждой группы |
| 3 | 3 победителя групп + лучший из вторых мест |
| 4 | 4 победителя групп |
| 5 и больше | только 4 лучших победителя групп |

- **При любом количестве групп в плей-офф должны попасть ровно 4 игрока.**
- **Игроков из разных групп сравниваем по итоговой сумме:** сначала очки, потом шары. Если и шары равны, назначается доп. матч. Проходит лучший.
- **Равенство игроков из одной группы** (очки и шары равны): между ними назначается **новый личный матч**. Результат их матча в группе для этого не используется. Если равных трое и больше, они играют новые матчи каждый с каждым.
- **Новый матч назначается только если от него зависит, кто выйдет в плей-офф.** Равенство за места, которые не проходят дальше, ничем не решается.
- **Если оба равных игрока проходят в плей-офф**, но от их порядка зависят пары полуфиналов, порядок определяется **жребием**. Админ может поправить пары вручную.
- **Если после новых матчей равенство осталось**, назначаются ещё матчи. Это повторяется, пока не определятся 4 лучших.
- **Ручная правка.** Администратор в любой момент может вручную назначить или заменить участников плей-офф, не дожидаясь доп. матчей.

### Пары полуфиналов (согласовано: «принимаю твой вариант»)
- **2 группы:** A1–B2 и B1–A2.
- **В остальных случаях:** участников упорядочивают по очкам и шарам, затем играют 1-й с 4-м и 2-й с 3-м.
- **3 группы:** «лучший второй» не должен сразу встретиться с победителем своей группы.

### Плей-офф
- Шары не учитываются, считается только победа.
- Сетка формируется автоматически, но админ может исправить её вручную.
- **Матч за 3-е место проводится.** В нём встречаются проигравшие в полуфиналах. Играется **до финала**.
- **Пьедестал на табло.** После финала табло показывает итоговые 1, 2 и 3 места.

### Стол
- **Игра идёт на одном столе.** Матчи играются по очереди, одновременно идёт только один.
- **Смена матча.** Когда администратор подтверждает победителя матча и выставляет шары, следующий матч из очереди считается начавшимся. Отдельной кнопки «Начать матч» нет.

## Прочие требования (согласовано)

- **Админы:** два администратора, у каждого свой логин и пароль. Вход с телефона запоминается на 30 дней. Права у админов одинаковые, учётные записи заводит программист заказчика.
- **Размещение:** на сервере программиста заказчика, домен **cubalibre.su**.
- **Технологии:** бэкенд на **Node.js** (Express), база **SQLite**, фронтенд на чистом JavaScript без сборки. Каркас развёрнут программистом заказчика, карта проекта в `CLAUDE.md`.
- **Разделение работы:** весь код приложения, включая схему базы, пишется в репозитории. Программист заказчика отвечает за сервер, домен и выкладку.
- **Схема базы** меняется только новыми файлами миграций в `migrations/`, правила в `CLAUDE.md`.
- **Живые обновления табло** через Server-Sent Events: админка меняет данные, сервер сразу рассылает новое состояние всем экранам.
- **HTTPS** на cubalibre.su и dev.cubalibre.su, сертификаты выпускаются и продлеваются автоматически.
- **Код** хранится в репозитории `kosear/Cuba-libre-tournament` на GitHub. Сервер сам забирает изменения каждые 15 секунд, выкладка — это `git push`.
- **Окружения:** ветка `dev` → dev.cubalibre.su для проверки, ветка `main` → cubalibre.su, это табло в баре. В `main` попадает только проверенное на dev. У каждого окружения своя база.
- **Табло:** показывается на телевизоре 16:9.
- **Админ-панель:** должна быть удобной с телефона. Экраны, для которых нет макетов (плей-офф, настройки, снятие игрока), делаются сразу в коде в стиле макетов.
- **Языки:**
  - табло и весь его дизайн — только на **английском**;
  - админ-панель на время тестирования — **русский и английский** с переключателем;
  - финальная версия админ-панели — **английский, индонезийский и русский** с переключателем;
  - язык админ-панели по умолчанию — **английский**, выбранный язык запоминается на телефоне;
  - индонезийский перевод делаю я, его проверит носитель языка в процессе использования.

## Новые функции (обсуждаем)

### 1. Генерация очереди матчей

Согласовано:
- **Матчи групп идут по кругу между группами:** матч группы A, потом B, потом C и так далее, затем снова A.
- **Равномерность.** Внутри группы матчи расставляются так, чтобы игроки играли равномерно, по возможности с равным интервалом. Один игрок не должен играть несколько матчей подряд.
- **Группы разного размера.** Когда в одной группе матчи закончились, круг продолжается по оставшимся группам.
- **Администратор может менять порядок матчей** как угодно. На телефоне это делается **перетаскиванием пальцем**, как точки маршрута в Google Картах.
- **Кнопка «Отложить»** переносит матч на 1 позицию дальше в очереди.
- **Новый игрок во время группового этапа:**
  - если остальные игроки группы уже сыграли все свои матчи, **в начало очереди ставится только его первый матч**. Остальные его матчи распределяются по очереди с интервалами по правилу равномерности. Если других матчей в очереди не осталось, он доигрывает подряд;
  - если остальные ещё не сыграли, его матчи встают в случайные позиции среди оставшихся матчей, но **с соблюдением равномерности**: не подряд и примерно с равными интервалами.
- **Доп. матчи** ставятся в очередь сразу после групповых.
- **Порядок плей-офф:** полуфинал 1, полуфинал 2, матч за 3-е место, финал.

### 2. Выбывание игрока и особые исходы

Согласовано:
- **Если игрок покинул турнир по любой причине**, каждому игроку его группы записывается победа над ним.
  - Это касается и уже сыгранных матчей: если выбывший ранее выиграл, результат меняется на его поражение.
- **Шары в матчах против выбывшего** — среднее количество шаров, оставшихся на столе у проигравших, за весь турнир. Оно рассчитывается после последней игры группы.
- **Особые исходы партии** (например, чёрный шар забит раньше времени) отдельно не обрабатываются. Администратор всегда записывает фактическое количество шаров, оставшихся у проигравшего.
- **Округление среднего:** до ближайшего целого, ровно посередине (например, 3,5) — в большую сторону.
- **До последней игры группы** в таблице за матчи с выбывшим учитывается текущее среднее. Как это выглядит — обсудим вместе с дизайном.
- **Выбывший остаётся в таблице группы.** Как он отображается — обсудим вместе с дизайном.
- **Выбывание в плей-офф:** соперник проходит дальше автоматически.
- **Замена игрока** (в админке кнопка «Заменить»): вместо игрока в группу приходит новый игрок с новым именем.
  - Все игры заменённого игрока аннулируются, в том числе результаты его соперников в этих играх: их победы и шары пропадают, с новым игроком они играют заново.
  - Заменённый игрок полностью исчезает из таблиц и с табло. В журнале действий замена остаётся, её можно отменить.
  - Несыгранные матчи заменённого снимаются из очереди. Если он играет прямо сейчас, этот матч снимается, начинается следующий.
  - Матчи нового игрока ставятся в очередь по тому же правилу, что и матчи игрока, добавленного во время группового этапа.
  - Можно заменить и игрока, который раньше выбыл: его технические поражения тоже аннулируются.
  - Только на групповом этапе. В плей-офф кнопки нет: там есть выбывание и ручная смена участников сетки.
- **Перевод в другую группу** (в админке кнопка «Отправить в другую группу») во время группового этапа:
  - все результаты игрока в старой группе аннулируются, матчи с ним аннулируются (у соперников тоже), из старой группы он исчезает;
  - в новой группе он играет со всеми, его матчи ставятся в очередь по правилу для добавленного игрока;
  - если в старой группе останется меньше 2 игроков, перевод запрещается с сообщением.
- **Замена игроком из другой группы = обмен местами:** в окне «Заменить» можно вместо нового имени выбрать игрока другой группы. Игроки меняются группами.
  - Правило аннулирования работает для обоих: результаты каждого в старой группе аннулируются, у соперников тоже.
  - Каждый в новой группе играет со всеми, матчи ставятся в очередь по правилу для добавленного игрока.
  - Если один из двух ранее выбыл, обмен запрещается с сообщением. Выбывшего можно заменить новым игроком.

### 3. Формирование групп

Согласовано:
- **Группы составляет администратор вручную** перед каждым турниром: сам задаёт количество групп и добавляет в них игроков.
- **Жеребьёвка не нужна.**
- **Матчи создаются кнопкой «Начать турнир»**, когда группы заполнены. До этого состав групп можно свободно менять.
- **Новый турнир.** Кнопка «Новый турнир» начинает с чистого листа. Старый турнир остаётся в базе, но нигде не показывается. Архив не нужен.

### 4. Журнал действий и простое редактирование

Согласовано:
- **Редактировать можно всё:** любые данные турнира (имена игроков, группы, результаты, шары, очки, очередь матчей, участники плей-офф и всё остальное) меняются из админ-панели. Ко всем данным одинаковый подход: открыл, поменял, сохранил.
- **Журнал действий администратора:** у каждого действия есть кнопка «Отменить».
- **Отмена линейная**, как Ctrl+Z: отменяются последние действия по порядку, от нового к старому.
- **Отмена отмены:** отменённые действия можно вернуть по порядку. Если после отмены сделано новое действие, отменённые вернуть уже нельзя.
- **Пример для ориентира:** сайт blindvalet (покерный).
- **Журнал общий для обоих админов.** «Отменить» отменяет последнее действие, даже если его сделал другой админ. В журнале видно, кто что сделал.

### 5. Надёжность

Согласовано:
- **При пропаже интернета** табло продолжает показывать последнее состояние, а администратор может продолжать вводить результаты. Они отправятся, когда связь восстановится.
- **Резервные копии** создаются автоматически.
- **Конфликт без интернета.** Если оба админа без связи изменили одно и то же (например, записали результат одного матча), сервер принимает первое пришедшее действие, второе отклоняет и показывает предупреждение.

## Дизайн табло

Согласовано:
- **Слайды сменяют друг друга по кругу.** Анимации переходов обсудим позже.
- **Групповой этап**, слайды в таком порядке:

  | Слайд | Длительность |
  |---|---|
  | Все группы на одном экране | 30 с |
  | Каждая группа отдельно, один слайд на группу | 10 с на группу |
  | «Следующий матч»: имена игроков | 10 с |
  | Плей-офф: с первого сыгранного матча в группах (до него слайда нет) | 10 с |

- **Текущий и следующий матч.** Из матчей в очереди без выставленного результата первый уже играется сейчас, а второй — «следующий».
- **Плей-офф.** Слайды групп не показываются. По кругу идут слайды «Следующий матч» и «Плей-офф».
- **После финала** показывается только слайд с пьедесталом. Пока вид пьедестала не обсуждён, делается простой вариант в стиле остальных слайдов: 1, 2 и 3 места крупно.
- **До старта турнира** показывается только экран-заглушка, без блока очереди.
- **Анимация заглушки** (скрипт в браузере, не видеофайл; бесконечная и неповторяющаяся):
  - белый фон, по центру логотип бара, без подписей;
  - время от времени мимо прокатываются бильярдные шары: объёмные (блик и тень), иногда один раз отскакивают от края экрана, если потом всё равно улетят за экран;
  - одновременно на экране не больше 2 шаров (включая биток);
  - некоторые шары врезаются в логотип — он чуть деформируется и быстро упруго возвращается к исходному виду;
  - некоторые шары катятся медленно и останавливаются рядом с логотипом; через некоторое время прилетает белый биток, выбивает такой шар, и оба улетают;
  - табло работает в браузере телевизора на Google TV — анимация должна быть лёгкой.
- **Логотип бара** есть на заглушке и в шапке табло. Файлы без фона: `docs/assets/cuba-libre-logo.svg` (вектор, перерисован по фото меню, масштабируется без потерь) и `docs/assets/cuba-libre-logo.png` (2720×1147). Возможны небольшие отличия от оригинала.
- **Шапка табло:** треугольник со звездой, логотип бара и подпись «Pool Tournament». На стартовом экране логотип пока не ставим. На заглушке логотип по центру — вокруг него строится анимация с шарами.
- **Медиафайлы.** Пока логотипа, видео и других файлов нет, используются заглушки.
- **Слайд «Все группы»** показывает максимум 4 группы. Если групп больше, оставшиеся показываются на следующем слайде (или слайдах).
- **Текущий матч на табло не показывается** (с 2026-10-10): ни слайда «Сейчас играют», ни карточки в блоке очереди. За столом и так видно, кто играет.
- **Слайд «Следующий матч»:** по центру крупно синим надпись NEXT MATCH, имена игроков только заглавными буквами. Группа матча — в заголовке слайда.
- **Слайд «Плей-офф»** оформлен как турнирная сетка: полуфиналы слева, линии ведут к финалу, матч за 3-е место под финалом.
- **Претенденты в плей-офф.** Пока группы не доиграны, в полуфиналах показываются те, кто прошёл бы, если бы группы закончились сейчас:
  серые имена, пунктирные рамки, подпись «If the groups ended now». Если за место равенство, показываются оба имени через «/»
  (больше двух — заглушка). У группы, где ещё не было игр, — заглушка («Winner Group B»). Когда группы доиграны, сетка обычная.
- **Стартовый экран сайта:** две кнопки — «Scoreboard» (режим табло для телевизора) и «Admin panel» (вход в админ-панель по паролю). Он открывается первым, до заглушки.
- **Порядок на телевизоре:** стартовый экран → «Scoreboard» → заглушка до старта турнира → после старта слайды по кругу.
- **Адреса:** стартовый экран — `/`, табло — `/board`, админ-панель — `/admin`. Телевизор можно сразу настроить на `/board`, тогда стартовый экран он пропускает.
- **Красный цвет** не используется для рамок и выделения важных блоков: он воспринимается как ошибка. Финал в сетке выделяется синим.
- **Справа всегда виден фиксированный блок с очередью.**
  - Сверху две карточки: «Next» — самая яркая и крупная; «After next» — следующий после него, серая, помельче.
    Матч, который играется сейчас, в очереди не показывается.
  - Остальные матчи медленно прокручиваются. Дойдя до конца очереди, список возвращается в начало и прокручивается снова.
  - Блок очереди и шапка не входят в слайд: при смене слайда они не перерисовываются, не мерцают, прокрутка очереди не сбрасывается. Меняется только содержимое слайда и заголовок в шапке.
- **Имена игроков крупнее** во всех блоках: таблицы групп, таблица пересечений, «Следующий матч», очередь, сетка плей-офф, пьедестал.
- **Таймера нет.**
- **Тема светлая.**
- **Цвета и стиль:** светлый фон, акценты голубоватым и красным. Можно использовать красный треугольник с белой звездой с флага Кубы.
- **Макеты** лежат в `docs/mockups/` и на доске Miro: https://miro.com/app/board/uXjVEceXFdg=/

### Таблица группы

- **Колонки:**

  | Имя | Игры | Победы | Шары |
  |---|---|---|---|

  «Шары» — дополнительные баллы за шары соперника на столе. Колонок «Итог» и «Место» нет: порядок строк сам показывает место.
- **Порядок строк** — по правилам турнира: сначала победы, при равенстве шары.
- **Один дизайн таблицы** на общем слайде и на слайде группы. Меняется только масштаб.
- **Лидер группы:** значок 🏆 рядом с именем, вся строка жирным шрифтом.
  - Если лидеров несколько (равны), значок получают все, кто ещё может попасть в плей-офф. Кто уже точно не проходит, значка не получает.
  - Других подсветок проходящих в плей-офф нет.
- **Выбывший игрок:** зачёркнутое серое имя, строка всегда внизу таблицы.
- **Шары по текущему среднему:** значок «≈», пока группа не доиграна.
- **Слайд группы:** две таблицы рядом.
  - Слева такая же таблица, как на общем слайде.
  - Справа таблица пересечений «кто кого обыграл». Клетка на пересечении строки игрока A и столбца игрока B показывает результат A против B:
    - победа — количество шаров **зелёным** цветом;
    - поражение — **0 чёрным**;
    - не играли — пустая клетка;
    - диагональ (игрок сам с собой) — серая клетка.
  - Фон клеток не раскрашивается, меняется только цвет текста.

## Не требуется

Проект некоммерческий, для локального турнира, без лишнего:
- лига и сезоны, архив турниров, накопительный рейтинг;
- страница игрока, уведомления, самостоятельная регистрация;
- публикация итогов в соцсетях;
- брендинг и спонсоры.
